# Сервер AMURA на Hoster.kz (переезд, вариант В — решение владельца 03.11.2026)

Подключение — без SSH из сессии разработчика: сервер сам забирает код с GitHub (репозиторий публичный,
у сервера нет прав на запись) и сообщает итог системе AMURA подписанными отчётами.

1. Владелец: Hoster.kz → сервер → «Консоль», вход root, одна команда:
   `curl -fsSL https://raw.githubusercontent.com/Mussarov402/amura-shop/main/deploy/bootstrap.sh | bash`
2. Сервер присылает публичные ключи и отпечаток в журнал Render (`/ops/hello`); разработчик закрепляет их PR-ом
   в `deploy/server-key.json` — после этого отчёты сервера (`/ops/report`) принимаются, ok и тревоги идут
   в Telegram-уведомления владельца.
3. Дальше всё — PR-ами: `deploy/stage` и `deploy/apply.sh`. Сервер проверяет GitHub раз в минуту.

Секреты: секретные части ключей сервера (`/etc/amura/*.key`) не покидают сервер. Ключи приложения (МойСклад, WB, Ozon…)
система AMURA передаст серверу зашифрованными его публичным ключом `box` — в чат и в репозиторий они не попадают.
Render остаётся запасным до отдельного слова владельца; переключение DNS — только после слова владельца «переключаем».

## Домены и сертификаты (deploy/nginx.sh, deploy/certs.sh)

nginx принимает amura.kz, www, opt, admin, api, server.amura.kz и отдаёт всё приложению; до сертификата — по http.
Таймер `amura-certs` (2 мин) выпускает сертификат Let's Encrypt домену, как только пробный файл виден снаружи:
до смены DNS проверку принимает Render и пересылает сюда (`ops.acme`), поэтому сертификаты готовы заранее.
`deploy/check.sh` — куда смотрит каждый домен и отвечает ли https; `check.sh local` — то же через nginx этого сервера.

## Ночь переезда (stage = live)

1. Render: `AMURA_READONLY=1` (записи → 503 «повторите через 15 минут», вебхуки повторятся) и `AMURA_STANDBY=1` (фон выключен).
2. PR `stage=live` → сервер: свежие переменные, финальная копия базы (своя база перед ней — в /var/backups/amura),
   сверка строк — ноль расхождений, иначе тревога и ожидание. Затем `app:app` с фоном, `PUBLIC_URL=https://api.amura.kz`.
   Копии с Render после этого запрещены (отметка /var/lib/amura/live).
3. Владелец меняет DNS: A amura.kz, www, opt, admin, api → 89.126.206.3 (записи AAAA удалить). Сводка доменов «🖥» приходит
   при каждом изменении.
4. Откат: PR `stage=db` (сервер снова в ожидании), на Render убрать AMURA_READONLY и AMURA_STANDBY, DNS — как было.
