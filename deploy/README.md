# Сервер AMURA на Hoster.kz (переезд, вариант В — решение владельца 03.11.2026)

Подключение — без SSH из сессии разработчика: сервер сам забирает код с GitHub (репозиторий публичный,
у сервера нет прав на запись) и сообщает итог системе AMURA подписанными отчётами.

1. Владелец: Hoster.kz → сервер → «Консоль», вход root, одна команда:
   `curl -fsSL https://raw.githubusercontent.com/Mussarov402/amura-shop/main/deploy/bootstrap.sh | bash`
2. Сервер присылает публичные ключи и отпечаток в журнал Render (`/ops/hello`); разработчик закрепляет их PR-ом
   в `deploy/server-key.json` — после этого отчёты сервера (`/ops/report`) принимаются, ok и тревоги идут
   в Telegram-уведомления владельца.
3. Дальше всё — PR-ами: `deploy/stage` и `deploy/apply.sh`. Сервер проверяет GitHub раз в минуту.

Секреты: секретные части ключей сервера (`/etc/amura/*.key`) не покидают сервер. Ключи приложения (МойСклад, WB, Ozon…)
система AMURA передаст серверу зашифрованными его публичным ключом `box` — в чат и в репозиторий они не попадают.
Render остаётся запасным до отдельного слова владельца; переключение DNS — только после слова владельца «переключаем».
