# Переезд с МойСклад на свою систему — журнал

Цель: панель admin.amura.kz + магазин amura.kz заменяют МойСклад (склад, документы, деньги), **не ломая работу магазина**.
МойСклад остаётся единственным источником правды, пока владелец явно не переключит модуль.

## Текущий этап

**Этап 1 — зеркало данных (только чтение).** Зеркало включено на проде (#114, 07.10 14:49 UTC). Загружаются товары, модификации, цены, штрихкоды, склады, остатки по складам, контрагенты; сверка — по кнопке и автоматически раз в сутки.

## Дорожная карта

1. Зеркало данных (только чтение) + отчёт сверки «наши цифры = МойСклад».
2. Разделы панели на своих данных, только просмотр: «Склад», «Финансы» — за флагами, по умолчанию выключены.
3. Свои операции с двойной записью (приёмка, списание, перемещение, инвентаризация, платежи, позже заказы/отгрузки): пишем в свою базу и сразу в МойСклад, с очередью повторов.
4. Переключение модуль за модулем («наша база главная») — только с разрешения владельца на конкретный модуль.
5. Отключение МойСклад и замена кассы (фискальные чеки) — только решение владельца.

Параллельно с этапами 2–4 — модуль «Касса» (см. ниже): свой экран продаж с фискализацией через ОФД Казахстана.

## Архитектура модулей

Всё новое (Склад, Финансы, Касса и дальше любые разделы) — **подключаемые модули**, чтобы систему можно было продавать другим магазинам и включать им только нужное.

- **Реестр модулей** (код): `id`, название, разделы панели (`views`), права сотрудников, поддерживаемые источники данных, зависимости (например, Касса → Склад).
- **Состояние в `setting`**: `mod_<id>` = `0/1` (включён, по умолчанию `0`), `mod_<id>_src` = `ms` / `own` (источник данных, по умолчанию `ms`).
  Существующий флаг `feat_mirror_sync` — служебный (загрузка зеркала), модулем не является; модули на «нашей базе» требуют, чтобы зеркало было включено и сверка сходилась.
- **Выключенный модуль** не виден в меню (`aside`, вкладки `.seg`, нижняя панель), его API отвечает 404, фоновые задачи не запускаются — ни на что не влияет.
- **Права**: у каждого модуля свои права (`stock`, `finance`, `pos`, `pos_refund`, `pos_zreport` …) добавляются в `team.PERMS` и в окно приглашения сотрудника; право модуля действует, только пока модуль включён.
- **Источник данных** — слой-адаптер на модуль: `source("stock").balance(product, store)` читает из МойСклад (как сейчас) или из нашей базы (`ms_*`, позже свои таблицы). Переключение `ms → own` — только с явного разрешения владельца на конкретный модуль (этап 4).
- **Настройки → «Модули»** (только владелец): список модулей с переключателями, выбором источника и статусом сверки. Телефон и компьютер.
- Первый шаг реализации: реестр + `GET/PUT /admin/api/modules` + раздел «Модули» без единого включаемого модуля (ничего не меняет), затем «Склад» (этап 2) как первый модуль.

## Модуль «Касса» (обязательный)

Пока работает Касса МойСклад на точке, модуль выключен. Фискализация — юридический вопрос, переключение только решением владельца.

- **К1. Провайдер фискализации** — общий интерфейс (`fiscal.py`): `open_shift`, `sale(check)`, `refund(check)`, `x_report`, `z_report`, `close_shift`, `status`; реализации-адаптеры: Webkassa, ReKassa и аналоги (выбор и ключи — в настройках модуля), плюс тестовый «песочный» провайдер. Чек хранится у нас с ответом ОФД (номер, фискальный признак, ссылка на чек).
- **К2. Свои таблицы**: `pos_shift` (смена, кассир, открыта/закрыта, наличные в кассе), `pos_check` + `pos_check_line` (продажа/возврат, оплата: наличные / карта / QR / смешанная, скидка, статус фискализации), `pos_queue` (повтор фискализации при сбое ОФД).
- **К3. Экран продаж (POS)** для телефона/планшета и компьютера: поиск товара, сканер штрихкода (камера и USB-сканер), корзина, скидка на позицию и на чек, оплата, сдача, печать/отправка чека (ссылка ОФД в WhatsApp/Telegram).
- **К4. Смена**: открытие, внесение/изъятие наличных, X-отчёт, Z-отчёт, закрытие; возвраты по чеку.
- **К5. Двойная запись (этап 3)**: каждая продажа/возврат дублируется в МойСклад как розничная продажа/возврат (без фискализации в МойСклад), чтобы остатки и «Обзор» сходились, пока МойСклад главный.
- **К6. Пилот**: включение модуля на одной точке параллельно с Кассой МойСклад — только решение владельца.

Права: `pos` (продавать), `pos_refund` (возвраты), `pos_zreport` (Z-отчёт, закрытие смены), `pos_discount` (скидки сверх лимита).

## Как устроено зеркало (`mirror.py`)

- База — та же, что у инбокса (`inbox.db()`: Postgres на Render, SQLite при `INBOX_SQLITE` в тестах). Миграции только добавляющие (`CREATE TABLE IF NOT EXISTS`).
- Флаг `feat_mirror_sync` в таблице `setting`. Включён на проде разово по решению владельца (#114, `mirror._autostart`): если ключа нет — `1`; выключенный вручную снова не включается. Пока он выключен, фоновый цикл ничего не запрашивает у МойСклад.
- Перед каждой страницей зеркало ждёт (до 30 с), пока в ограничителе `oh.ms` свободно хотя бы 2 места из 4 — сайт и заказы не стоят в очереди за зеркалом.
- Из МойСклад — **только GET** через `oh.ms` (ретраи, семафор, общий с сайтом).
- Бережно к лимитам: страницы по 200 строк, пауза 1 с между страницами, не больше 10 страниц одной сущности за проход;
  во время первичной загрузки проход раз в 2 минуты, потом раз в 10 минут.
- Инкрементальная загрузка по `updated` (время МойСклад — Москва; сравнение строк, без перевода поясов):
  `filter=updated>=cursor`, `order=updated,asc`, `offset=skip`, где `skip` — сколько строк ровно с этим `updated` уже загружено.
  Так изменения в МойСклад во время загрузки не сдвигают страницы.
- Раз в сутки — полный проход заново; то, чего в нём не было, помечается `deleted=1` (удалено в МойСклад).
- Остатки — целиком из отчёта `/report/stock/bystore/current` (`stock` и `reserve`), таблица заменяется в одной транзакции.

### Сверка

`/admin/api/mirror/recon` (в фоне) и автоматически раз в сутки, когда загрузка догнала МойСклад, сравнивает:
- число товаров, модификаций и контрагентов не в архиве — с `meta.size` МойСклад;
- остатки по каждому товару (сумма по складам) — с отчётом `/report/stock/all/current`; до 10 самых больших расхождений;
- цены опт/розница товаров, которые сейчас показывает сайт, — с ценами в зеркале.

Дальше (после документов): продажи за день (отгрузки + чеки − возвраты, как на «Обзоре»), долги клиентов (`/report/counterparty`).

### Панель

Раздел «Своя база» — только владелец, в меню его нет: открывается ссылкой **admin.amura.kz/admin#mirror**.
Там: включение загрузки, состояние по сущностям, кнопки «Обновить сейчас» и «Сверить с МойСклад», результат сверки, поиск товара с остатками по складам.
Проверен на 390 и 1280 px.
