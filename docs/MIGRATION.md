# Переезд с МойСклад на свою систему — журнал

Цель: панель admin.amura.kz + магазин amura.kz заменяют МойСклад (склад, документы, деньги), **не ломая работу магазина**.
МойСклад остаётся единственным источником правды, пока владелец явно не переключит модуль.

## Текущий этап

**Этап 1 — зеркало данных (только чтение).** Сделан первый шаг: товары, модификации, цены, штрихкоды, склады, остатки по складам + сверка.

## Дорожная карта

1. Зеркало данных (только чтение) + отчёт сверки «наши цифры = МойСклад».
2. Разделы панели на своих данных, только просмотр: «Склад», «Финансы» — за флагами, по умолчанию выключены.
3. Свои операции с двойной записью (приёмка, списание, перемещение, инвентаризация, платежи, позже заказы/отгрузки): пишем в свою базу и сразу в МойСклад, с очередью повторов.
4. Переключение модуль за модулем («наша база главная») — только с разрешения владельца на конкретный модуль.
5. Отключение МойСклад и замена кассы (фискальные чеки) — только решение владельца.

## Как устроено зеркало (`mirror.py`)

- База — та же, что у инбокса (`inbox.db()`: Postgres на Render, SQLite при `INBOX_SQLITE` в тестах). Миграции только добавляющие (`CREATE TABLE IF NOT EXISTS`).
- Флаг `feat_mirror_sync` в таблице `setting` (по умолчанию `0`). Пока он выключен, фоновый цикл ничего не запрашивает у МойСклад.
- Из МойСклад — **только GET** через `oh.ms` (ретраи, семафор, общий с сайтом).
- Бережно к лимитам: страницы по 200 строк, пауза 1 с между страницами, не больше 10 страниц одной сущности за проход;
  во время первичной загрузки проход раз в 2 минуты, потом раз в 10 минут.
- Инкрементальная загрузка по `updated` (время МойСклад — Москва; сравнение строк, без перевода поясов):
  `filter=updated>=cursor`, `order=updated,asc`, `offset=skip`, где `skip` — сколько строк ровно с этим `updated` уже загружено.
  Так изменения в МойСклад во время загрузки не сдвигают страницы.
- Раз в сутки — полный проход заново; то, чего в нём не было, помечается `deleted=1` (удалено в МойСклад).
- Остатки — целиком из отчёта `/report/stock/bystore/current` (`stock` и `reserve`), таблица заменяется в одной транзакции.

### Таблицы (сделано)

| Таблица | Что | Ключ |
|---|---|---|
| `ms_product` | товары и модификации (`kind` = product / variant, `parent_id` у модификации), код, артикул, название, папка, архив, `prices` JSON {тип цены: ₸}, закупочная цена, `barcodes` JSON, `updated`, `deleted`, `seen` | `id` (uuid МойСклад) |
| `ms_store` | склады | `id` |
| `ms_stock` | остаток и резерв по складам | `product_id, store_id` |
| `ms_sync` | состояние синхронизации по сущностям: курсор, полный проход, последний успех, ошибка | `entity` |
| `ms_recon` | результаты сверок (JSON) | `id` |

### Таблицы (план, следующие шаги этапа 1)

| Таблица | Что | Откуда |
|---|---|---|
| `ms_agent` | контрагенты: имя, телефон, теги, группа, `updated` | `/entity/counterparty` |
| `ms_doc` | шапки документов: `type` (customerorder, demand, retaildemand, salesreturn, retailsalesreturn, supply, loss, enter, move, inventory, paymentin/out, cashin/out), номер, `moment`, контрагент, склад, сумма, `applicable`, статус, `updated`, `deleted` | `/entity/<type>` инкрементально по `updated` |
| `ms_doc_line` | позиции документов: товар, кол-во, цена, скидка | `/entity/<type>/<id>/positions` (только для изменённых документов) |
| `ms_payment_link` | связи платежей с документами (`operations`) | у платежей |
| `ms_account` | кассы/счета организации | `/entity/organization/<id>/accounts`, `retailstore` |

Удалённые документы ловить через `/audit` (события `delete`) или суточный полный проход за последние N дней.

### Сверка

`/admin/api/mirror/recon` (в фоне) сравнивает:
- число товаров и модификаций не в архиве — с `meta.size` МойСклад;
- остатки по каждому товару (сумма по складам) — с отчётом `/report/stock/all/current`; до 10 самых больших расхождений;
- цены опт/розница товаров, которые сейчас показывает сайт, — с ценами в зеркале.

Дальше (после документов): продажи за день (отгрузки + чеки − возвраты, как на «Обзоре»), долги клиентов (`/report/counterparty`).

### Панель

Раздел «Своя база» — только владелец, в меню его нет: открывается ссылкой **admin.amura.kz/admin#mirror**.
Там: включение загрузки, состояние по сущностям, кнопки «Обновить сейчас» и «Сверить с МойСклад», результат сверки, поиск товара с остатками по складам.
Проверен на 390 и 1280 px.
